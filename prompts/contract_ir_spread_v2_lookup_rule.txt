---------------------
AST grammar (ONLY these 3 node types)
---------------------
1) Literal node:
   {"lit": {"type": "...", "value": ...}}

2) Variable node:
   {"var": "name"}

3) Operator node:
   {"op": "op_name", "args": [<node>, ...]}

Literal types (v0.2):
- "rate" | "bps" | "decimal" | "money" | "integer" | "string" | "bool" | "date"

NUMERIC LITERALS MUST BE STRINGS.

---------------------
Operator allowlist (v0.2)
---------------------
Conversions:
- bps_to_rate(bps)
  - returns rate decimal: bps / 10000

Tables:
- lookup_rule(table_id, predicate_col, value_col)
  - Evaluates predicate_col (bool AST) for each row using the function's input variables
  - Exactly ONE row must match (predicate evaluates to true)
  - table_id/predicate_col/value_col MUST be AST string literal nodes:
    - {"lit":{"type":"string","value":"..."}}

Conditionals / comparisons for building predicates (only if needed):
- if(cond, then_expr, else_expr)
- eq/lt/lte/gt/gte
- and/or/not

=====================
RULE TABLE POLICY (FOR MULTI-DIMENSION CONDITIONS)
=====================
- If the excerpt expresses conditions over multiple inputs (e.g., two ratios) and the TASK asks for a deterministic schedule:
  - Represent it as a RULE TABLE:
    - each row has:
      - rule_label (string): short label for the rule (from excerpt)
      - predicate (bool): a boolean AST expression that references ONLY function args (variables) and numeric literals
      - margin_bps (bps): the margin percentage converted to bps (e.g., 2.50% => 250 bps)
  - Use lookup_rule(...) to pick the single matching row.
- Do NOT invent rules not present in the excerpt.

Predicate column encoding (IMPORTANT):
- The predicate cell MUST be an AST expression that evaluates to bool (operator node), for example:
  {"op":"lt","args":[{"var":"interest_coverage_ratio"},{"lit":{"type":"decimal","value":"1.75"}}]}
- Do NOT put the predicate in a string literal.
- Preserve boolean connectors from the excerpt:
  - If the excerpt says "OR", use {"op":"or", ...}
  - If the excerpt says "AND", use {"op":"and", ...}

=====================
MISSING / AMBIGUOUS DATA POLICY
=====================
- If the TASK requires rule rows or margin values that are NOT explicitly present in the provided CONTEXT, DO NOT GUESS.
- Instead: emit a blocking open_item describing what is missing and return:
  - tables = [] (empty)
  - derived = [] (empty)
