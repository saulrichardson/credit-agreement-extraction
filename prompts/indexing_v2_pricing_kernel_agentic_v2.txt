You are reading an entire credit agreement exhibit (often from EDGAR, but not always).

The document is presented as **anchored blocks**. Each block begins with an anchor marker on its own line:

`[[A0001]]`

The block text follows on subsequent lines until the next `[[A####]]` marker.

When you answer:
- Use the **exact** anchor IDs (e.g., `"A0001"`) from the markers.
- Do **not** invent, transform, or renumber anchor IDs.
- Return **JSON only** (no prose, no markdown, no code fences).

## Goal

Select anchor IDs that let downstream extractors reliably encode (with provenance):
- pricing (base rate definitions, spreads/margins, fee schedules)
- financial covenants (tests, thresholds, timing, and compute-critical definitions)

This is a **single-pass selection** task. There is no downstream anchor backfill.
If you omit compute-critical anchors (especially tables/grids or covenant threshold paragraphs), downstream will be incomplete.

## How to work (internal procedure; do not output)

Work in this order:

1) **Locate a Definitions / Glossary section (if any)**
   - If there is a dedicated definitions section (often “SECTION 1. DEFINITIONS”), set `definitions_anchor_range` to the contiguous span.
   - This range is a pointer; you still must select the specific anchors needed for pricing/covenants.

2) **Pricing: Base rate / benchmark definitions**
   - Find anchors that define benchmark/base-rate computation mechanics (ABR/Base Rate, Prime, Fed Funds, SOFR/Term SOFR/Daily Simple SOFR, Adjusted rates, rounding, reserve adjustments).
   - Prefer the primary definitions (including defined terms) over later cross-references.

3) **Pricing: Spread / margin schedules**
   - Find anchors that define pricing spreads/margins (Applicable Margin / Applicable Rate).
   - If a schedule is expressed as a table/grid/tier list, include the anchors containing the actual numeric schedule.
   - Include adjacent anchors needed to interpret the schedule (headers/row labels/footnotes/continuations).

4) **Pricing: Fee schedules**
   - Find anchors defining borrower-paid fees (commitment/unused/utilization/LC/fronting/facility/admin fees if borrower-paid).
   - If a fee schedule is expressed as a table/grid/tier list, include the anchors containing the actual numeric schedule.
   - Include adjacent anchors needed to interpret the schedule (headers/row labels/footnotes/continuations).

5) **Financial covenants**
   - Find anchors that state explicit numeric/ratiometric requirements (max/min leverage, coverage, liquidity, etc.), including step-downs and testing timing/frequency.
   - Include compute-critical definitions/mechanics needed to evaluate compliance **when referenced by the covenant**.
     - Do NOT dump broad accounting definitions unless the covenant test actually depends on them (e.g., select the defined term anchor for “Consolidated EBITDA” if the covenant uses it).
     - CRITICAL: If a covenant threshold is itself a defined term (e.g., “Required Tangible Net Worth”, “Applicable Required Amount”, “Required Leverage Ratio”),
       you MUST include the anchor where that defined term is defined in `financial_covenant_anchors` (not only inside `definitions_anchor_range`).
   - Include “springing” / conditional covenant language when present.

6) **Selection discipline (internal; do not output)**
   - Prefer completeness for each localized concept (definition + table + footnotes), but avoid sweeping entire unrelated schedules/annexes.
   - For `metadata_anchors`, include only anchors needed to identify parties/roles/caption (avoid large unrelated tables unless they enumerate parties/roles).

7) **Self-check (internal; do not output)**
   - If you selected an intro/heading that says “set forth below / in the following table/grid”, ensure you also selected the anchor(s) that contain the actual table/grid values.
   - If you selected a clause that references a defined term (e.g., “Applicable Margin”), ensure you also selected the anchor(s) where that term is defined (and any schedule embedded in that definition).
   - If you selected a financial covenant that references a defined term threshold (e.g., “Required Tangible Net Worth”), ensure the definition anchor is included in `financial_covenant_anchors`
     so downstream can encode a computable threshold from the excerpt pack (A1 mode).
   - Ensure `pricing_anchors` is a union-style bucket: it should include (or strongly overlap with) the anchors in `base_rate_anchors`, `spread_anchors`, and `fee_anchors`.

## Output buckets

Select anchor IDs into the buckets below. Only include anchors where the anchored text itself contains relevant information (numbers, defined terms, mechanics, tables, formulas, or explicit cross-references).

It is OK (and expected) for the same anchor to appear in multiple buckets.

### (0) `definitions_anchor_range` — dedicated glossary/definitions section span (optional)

If (and only if) the agreement contains a dedicated definitions/glossary section where terms are defined, provide a contiguous anchor range that covers that definitions section.

Output shape:
- If applicable: `"definitions_anchor_range": {"start_anchor": "A....", "end_anchor": "A...."}`
- If not applicable: `"definitions_anchor_range": null`

### (1) `metadata_anchors` — document + parties + roles + execution details

Include anchors that capture who/what the document is and who the parties are (Borrower, Guarantor, Lenders, Administrative Agent, etc.), including signature blocks only when they enumerate parties/roles.

### (2) `fundamental_anchors` — core facility structure (non-pricing)

Include anchors describing facility structure: types, commitments/amounts, maturity, availability period, key lifecycle mechanics.

### (3D) `pricing_anchors` — all borrower economics (union bucket)

Include anchors that define or affect anything the borrower pays (interest economics + fees + compute-critical definitions/mechanics).

### (3A) `base_rate_anchors` — benchmark/base-rate definitions + compute-critical mechanics

Include anchors defining benchmark/base-rate computation mechanics.

### (3B) `spread_anchors` — spreads/margins only (Applicable Margin/Applicable Rate schedules)

Include anchors defining spread/margin schedules and mechanics. If there is a numeric schedule, include the anchor(s) containing the numeric schedule itself.

### (3C) `fee_anchors` — fee rates/schedules only

Include anchors defining borrower-paid fee rates/schedules and mechanics. If there is a numeric schedule, include the anchor(s) containing the numeric schedule itself.

### (4) `financial_covenant_anchors` — numeric tests/limits including needed definitions/mechanics

Include anchors with explicit numeric covenant tests/limits, plus the definitions/mechanics needed to compute them.
