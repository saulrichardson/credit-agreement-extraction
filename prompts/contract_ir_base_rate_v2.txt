You are converting credit agreement excerpts into a strictly-validated JSON intermediate representation (ContractIR v0.2).

Return JSON ONLY. No markdown. No commentary. No code fences.

=====================
CONTRACTIR v0.2
=====================

Top-level keys (must all be present; use empty arrays when needed):

---------------------
Provenance rules
---------------------
- Every derived function MUST include source_refs (non-empty list of anchor IDs like "A0123").
- source_refs / anchor_ids must use only the anchor IDs shown in the CONTEXT blocks.

---------------------
Semantic role (derived functions)
---------------------
Every derived function MUST include semantic_role with one of:
- base_rate     (benchmark/base rate definition, e.g., ABR, Adjusted LIBOR)
- spread        (pricing spread/margin component only)
- fee_rate      (facility fee / commitment fee / letter of credit fee rate, etc.)
- all_in_rate   (base rate + spread combined)
- other

For this BASE RATE pass: semantic_role MUST be "base_rate".

---------------------
AST grammar (ONLY these 3 node types)
---------------------
1) Literal node:
   {"lit": {"type": "...", "value": ...}}

2) Variable node:
   {"var": "name"}

3) Operator node:
   {"op": "op_name", "args": [<node>, ...]}

IMPORTANT: There are two different kinds of "args" in this schema:
- In an AST operator node (the object with `"op": "..."`), `"args": [...]` MUST contain ONLY AST nodes (lit/var/op). Do NOT use bare strings or numbers.
- In `derived[*]` function signatures, `derived[*].args` is an array of argument objects: `{"name":"...","type":"..."}` (NOT AST nodes).

Literal types (v0.2):
- "rate" | "bps" | "decimal" | "money" | "integer" | "string" | "bool" | "date"

NUMERIC LITERALS MUST BE STRINGS.
Examples:
- {"lit":{"type":"rate","value":"0.0525"}}   # 5.25% as a decimal rate
- {"lit":{"type":"bps","value":"37.5"}}     # 37.5 bps
- {"lit":{"type":"decimal","value":"1.00"}}
- {"lit":{"type":"integer","value":"16"}}

---------------------
Operator allowlist (v0.2)
---------------------
Core math:
- add(x,y,...)
- sub(x,y,...)
- mul(x,y,...)
- div(x,y,...)
- max(x,y,...)
- min(x,y,...)

External series:
- index(series_id, date)
  - series_id MUST be a string literal (e.g., {"lit":{"type":"string","value":"PrimeRate"}})
  - date MUST be a variable declared as type=date (NO hardcoded date literals)
  - BOTH args MUST be AST nodes (never bare strings)
  - Example:
    {"op":"index","args":[{"lit":{"type":"string","value":"PrimeRate"}},{"var":"date"}]}
  - NOTE: The indices[] declaration list uses plain strings:
    {"series_id":"PrimeRate","unit":"rate","description":null}
  - If you use index(..., {"var":"date"}), then derived.args MUST include {"name":"date","type":"date"} (use the name exactly "date").

Rounding:
- round_up_to_increment(x, increment)
  - increment is a numeric literal (string), e.g.:
    - next higher 1/100th of 1% => increment = 0.0001
    - next 1/16 of 1% => increment = 0.000625

Conditionals (only if needed):
- if(cond, then_expr, else_expr)
- eq/lt/lte/gt/gte
- and/or/not

---------------------
IMPORTANT typing/unit rules
---------------------
- Every indices[] entry MUST include unit (schema requirement).
  - For interest-rate indices like Prime, SOFR, Fed Funds, NYFRB, etc: unit MUST be "rate".
  - Never use unit="percent" (invalid). Use unit="rate".
- Reserve percentage inputs (e.g., "reserve_pct") MUST be decimal (e.g., 0.10).
- The constant 1.00 used in expressions like (1.00 - reserve_pct) MUST be a decimal literal (type=decimal), not a rate.
- For add/sub operations where the intent is "rate plus/minus rate", EVERY operand MUST be kind=rate.
  - Example: Federal Funds + 1/2 of 1% MUST be:
    add(index(FederalFundsRate,date), {"lit":{"type":"rate","value":"0.005"}})
  - Do NOT add a decimal literal to a rate (that will fail evaluation).

---------------------
Numeric literal formatting (STRICT)
---------------------
- Do NOT include "%" signs (or "$", commas) inside numeric literal strings.
  - Example: 0.0700% MUST be encoded as {"lit":{"type":"rate","value":"0.0007"}} (not "0.0700%").

---------------------
Floors / caps (when explicitly stated)
---------------------
- If the excerpt explicitly states a floor/cap on a base rate (e.g., “if ABR would be less than 1.00%, deemed 1.00%”),
  encode it using max(...) / min(...) rather than omitting it.

=====================
ONE-OFF CONDITIONS POLICY (OPEN ITEMS)
=====================
- If the excerpt contains a conditional clause that depends on external state / document sections / availability
  (e.g., benchmark replacement status, publication availability, discretionary determinations),
  DO NOT encode that branch logic as "if" in this pass unless the TASK explicitly instructs you to.
- Instead: record the issue as an open_item (with source_refs) and keep the base rate formula for the primary case.
- If the excerpt contains publication / availability fallbacks (e.g., "has not been published", "Benchmark Replacement Date"),
  you MUST include at least one blocking open_item describing the missing execution logic (do not guess date shifting).

---------------------
OPEN_ITEMS schema reminder (v0.2)
---------------------
Each open_items entry MUST be an object with:
- issue (string, required)
- source_refs (array of anchor ids, required; non-empty)
- suggested_parameters (array of strings, required; can be empty)
- blocking (boolean, required)

Example:
{
  "issue": "Term SOFR publication fallback requires lookback days; not encoded without date-shifting support.",
  "source_refs": ["A0001"],
  "suggested_parameters": ["term_sofr_is_published", "term_sofr_fallback_lookback_days"],
  "blocking": true
}
