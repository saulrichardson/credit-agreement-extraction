You are converting credit agreement excerpts into a strictly-validated JSON intermediate representation (ContractIR v0.2).

Return JSON ONLY. No markdown. No commentary. No code fences.

=====================
SCOPE (SPREAD / MARGIN ONLY)
=====================
- Only encode pricing spreads / margins / pricing grids (NOT fees, and NOT underlying benchmark/base rate definitions).
- Every derived function MUST have semantic_role = "spread".
- indices SHOULD usually be [] unless the TASK explicitly requires series.

=====================
CONTRACTIR v0.2
=====================

Top-level keys (must all be present; use empty arrays when needed):
- schema_version (must be "contract_ir_v0_2")
- contract_id  (MUST equal the item_id from TASK)
- sources
- indices
- tables
- derived
- open_items

cashflows is optional and MAY be omitted.

---------------------
Provenance rules
---------------------
- Every derived function MUST include source_refs (non-empty list of anchor IDs like "A0123").
- Every table row MUST include source_refs (non-empty list of anchor IDs).
- source_refs / anchor_ids must use only the anchor IDs shown in the CONTEXT blocks.

---------------------
Semantic role (derived functions)
---------------------
Every derived function MUST include semantic_role with one of:
- base_rate     (benchmark/base rate definition)
- spread        (pricing spread/margin component only)
- fee_rate      (facility fee / commitment fee / letter of credit fee rate)
- all_in_rate   (base rate + spread combined)
- other

For this SPREAD pass: semantic_role MUST be "spread".

---------------------
AST grammar (ONLY these 3 node types)
---------------------
1) Literal node:
   {"lit": {"type": "...", "value": ...}}

2) Variable node:
   {"var": "name"}

3) Operator node:
   {"op": "op_name", "args": [<node>, ...]}

Literal types (v0.2):
- "rate" | "bps" | "decimal" | "money" | "integer" | "string" | "bool" | "date"

NUMERIC LITERALS MUST BE STRINGS.

---------------------
Operator allowlist (v0.2)
---------------------
Conversions:
- bps_to_rate(bps)
  - returns rate decimal: bps / 10000

Tables:
- lookup(table_id, key_column, key_value, value_column)
  - exact match on key_column == key_value (string equality)
  - table_id/key_column/value_column are string literals

Table argument encoding (IMPORTANT):
- table_id, key_column, and value_column MUST be AST string literal nodes:
  - {"lit":{"type":"string","value":"..."}}
- key_value is usually a variable node, e.g. {"var":"rating"} or {"var":"status_code"}.

Conditionals (only if needed):
- if(cond, then_expr, else_expr)
- eq/lt/lte/gt/gte
- and/or/not

=====================
2D / MULTI-ROW TABLE POLICY
=====================
- If the excerpt contains a table with multiple loan types / multiple rows:
  DO NOT GUESS which row to use.
  - If the TASK does NOT explicitly tell you which row label to extract: emit a blocking open_item and stop (tables=[] and derived=[]).
  - If the TASK tells you which row label to extract: extract ONLY that row.

=====================
MISSING DATA POLICY (NO GUESSING)
=====================
- If the TASK asks for rows/cells that are NOT explicitly present in the provided CONTEXT, DO NOT GUESS.
- Instead: emit a blocking open_item describing what is missing and set:
  - tables = [] (empty)
  - derived = [] (empty)

---------------------
OPEN_ITEMS schema reminder (v0.2)
---------------------
Each open_items entry MUST be an object with:
- issue (string)
- source_refs (array of anchor ids; non-empty)
- suggested_parameters (array of strings; required; can be empty)
- blocking (boolean)

=====================
STATUS GRID POLICY (columns like "Level I Status" .. "Level VI Status")
=====================
- If the table axis is a set of Status columns:
  - Include BOTH:
    - status_code: Roman numeral only ("I","II","III","IV","V","VI")
    - status_label: exact header text (e.g., "Level V Status")
  - Prefer lookup keyed by status_code.
