=== HOW TO INTERPRET TABLES (MOST IMPORTANT) ===
Tables come in two common shapes:

(A) ROWS ARE TIERS (metric bucket rows)
Example headers: "Debt/Cash Flow Ratio | Applicable Margin", or
  "Consolidated Secured Net Leverage Ratio | Base Rate Loans | Eurocurrency Rate Loans"
In this case:
- Each row after the header is ONE tier.
- The tier’s conditions come from the row bucket text (e.g., ">= 3.00:1.0", "< 3.00:1.0").
- Each non-first column corresponds to a separate rate series:
  - "Base Rate Loans" => a margin rate with base_rate="Base Rate" (base_rate_type="prime")
  - "Eurocurrency Rate Loans" => a margin rate with base_rate="Eurocurrency Rate" (base_rate_type="libor" if "LIBOR"/"Eurocurrency" appears)
  - "Commitment Fee" => a fee rate with fee_basis="undrawn" or "facility_commitment" (choose the best match from text)

(B) COLUMNS ARE TIERS (status columns / rating columns)
Example: columns "Level I Status ... Level VI Status" and rows like:
  "Term Benchmark Loans, RFR Loans, and Money Market Loans" and "ABR Loans ..."
In this case:
- Each column heading is ONE tier (tier_id can be "Level I Status" etc).
- Row labels correspond to separate rates:
  - Row contains "Term Benchmark" or "RFR" => margin rate, base_rate="Term SOFR" if present, else "Term Benchmark"
  - Row contains "ABR" => margin rate, base_rate="ABR" (base_rate_type="prime")
  - A separate single-row table referenced as "Facility Fee Rate" => fee rate, fee_basis="facility_commitment"
  - "L/C Fee Rate" tables => fee rate, fee_basis="letters_of_credit"
