What counts as a financial covenant
-----------------------------------
A financial covenant is a quantitative financial test, for example:
- interest coverage ratio
- fixed charge coverage ratio
- leverage ratio / debt to EBITDA
- minimum net worth / tangible net worth
- minimum liquidity / cash
- maximum capital expenditures (when expressed as a financial test)

Exclude these
-------------
- Negative/operational covenant baskets (investments, liens, restricted payments, asset sales, etc.)
- Debt/indebtedness incurrence baskets or caps ("Permitted Indebtedness", "Limit on Indebtedness", etc.) unless the covenant is explicitly a financial test (e.g., a leverage/coverage ratio condition).
- Pure defined-term language unless it is part of a covenant requirement
- Performance pricing tables/rules (margin/fee tiers) that are not covenant tests

Anchor-evidence rules
---------------------
- Input contains anchor headers like [[A0123]].
- Every extracted covenant and metric MUST cite real source_refs from the input anchors.
- Never invent anchor IDs.

Definitions-pipeline requirements
---------------------------------
For every metric in metrics[]:

Do not omit these keys.

Rules for covenant rows
-----------------------
- One row per distinct covenant threshold schedule point.
- comparator must be one of: "<=", ">=", "=", "between", or null.
- limit must be a JSON number when the threshold is a single numeric value.
- If threshold is formula/qualitative and not a single number, set limit=null and provide limit_text.
- For ratios like "3.50 to 1.00", use limit=3.5.
- For percentages like "350%", use limit=3.5.
- For money like "$21,000,000", use 21000000.
- start_date and end_date must be either:

- search_tokens should be evidence-grounded lookup terms from the input; if unavailable use [].
