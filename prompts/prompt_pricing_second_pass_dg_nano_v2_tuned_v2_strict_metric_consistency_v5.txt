=== HOW TO INTERPRET TABLES (MOST IMPORTANT) ===
Tables come in two common shapes:

(A) ROWS ARE TIERS (metric bucket rows)
Example headers: "Debt/Cash Flow Ratio | Applicable Margin", or
  "Consolidated Secured Net Leverage Ratio | Base Rate Loans | Eurocurrency Rate Loans"
In this case:
- Each row after the header is ONE tier.
- The tier’s conditions come from the row bucket text (e.g., ">= 3.00:1.0", "< 3.00:1.0").
- Each non-first column corresponds to a separate rate series when the column headers clearly identify loan types
  (e.g., "Base Rate Loans", "Eurocurrency Rate Loans", "Commitment Fee").
- Some tables show ONLY one column called "Applicable Margin" (no loan type in header). In that case, you MUST use the
  surrounding prose in the anchors to determine which loan type(s) that table applies to. Do NOT assume it applies to
  every loan type if the prose carves out fixed margins for certain loan types.

(B) COLUMNS ARE TIERS (status columns / rating columns)
Example headers: "Level I | Level II | Level III | ..."
In this case:
- Each column is ONE tier.
- The column header is the tier_id/display.
- conditions MUST be null unless explicit numeric ratio boundaries appear in the input.

Multi-metric financial tables:
- Some agreements adjust pricing based on more than one financial test (e.g., a tier row can reference BOTH an interest coverage ratio and a fixed charge coverage ratio, using AND/OR language).
- When this occurs, include condition atoms for each metric threshold and keep the tier.display text faithful to the agreement language so the boolean structure is not lost.

=== REGIMES / EFFECTIVE DATE PERIODS ===

3) For each facility.rate object, include a "condition" object when it applies only to a specific regime:

PricingRegime is a synthetic routing metric (not an agreement-defined term), but definitions-v2 still needs it to be searchable:

  - Set PricingRegime.search_tokens to 3–6 verbatim micro-phrases from the same anchors.
  - Do NOT leave BOTH contract_term="" and search_tokens=[].

Hard requirement:
- If you emit ANY rate.condition with metric "PricingRegime", you MUST include a metrics[] entry named exactly "PricingRegime".

Regime-specific tier scheme rule (IMPORTANT):
